給 **GitHub Pages** 用的版本：左邊是 pygbag 編譯的網頁遊戲，右邊是**完全離線**的數字人小科。
沒有伺服器、沒有 API key、不需要安裝任何東西 —— 打開網址就能玩、能問。

> 來源：`D:/Wen/EduHK/6064/FINAL/earth-hk-combined`（Python + Gradio 版）。
> 這個資料夾是**建置產物**，6064 的原始碼沒有被改動；
> 小科的答案、詞庫、題庫都從 6064 抽出來，所以兩邊不會變成兩套說法。

## 二、本機預覽（看效果用）

**必須用 HTTP 開，不能雙擊 `index.html`。** 遊戲是 wasm，`file://` 下載不到資源；
小科本身可以雙擊開，但整頁會缺遊戲。

```bash
cd D:/Wen/EduHK/6066/INT6066_FINAL
python -m http.server 8080
# 瀏覽器打開 http://127.0.0.1:8080/
```

手機想一起看：`python -m http.server 8080 --bind 0.0.0.0`，
然後手機連同一個 Wi-Fi 開 `http://<電腦 IP>:8080/`。

## 三、部署到 GitHub Pages（三步）

細節與排錯見 [`部署-GitHub-Pages.md`](部署-GitHub-Pages.md)。

1. 在 GitHub 建一個 **public** 倉庫（免費 Pages 需要公開）。
2. 把這個資料夾推上去（`git init` 已做好並有第一次提交）：
   ```bash
   git remote add origin https://github.com/<你的帳號>/<倉庫名>.git
   git branch -M main
   git push -u origin main
   ```
3. 倉庫 → **Settings → Pages → Source 選「GitHub Actions」**。
   推送會自動觸發 `.github/workflows/pages.yml`，約 1 分鐘後得到
   `https://<你的帳號>.github.io/<倉庫名>/`。

## 四、改了知識庫之後怎麼同步

6064 的知識庫或關卡文案一改，這裡要重跑一次（只讀 6064，不會改它）：

```bash
cd D:/Wen/EduHK/6066/INT6066_FINAL
python 工具-從6064重新生成.py
```

它會重寫 `xiaoke-data.js`、`index.html`，並重新複製 `game/`、`assets/`。
看到「仍有絕對路徑未改」就表示 6064 的 `index.html` 新增了 `/xxx` 這種絕對路徑，
要在腳本的替換清單補一條。

`資料-中英補充.json` 的鍵必須跟知識庫 `#P-xx` 的標題**完全一致**；
改了詞條名而沒改這裡，腳本會印出警告（不會壞，只是那條會退回粵語或通用句）。
`資料-對齊補充.json` 的 `quiz_life[].key`、`faq_alias` 的題目名同樣要對得上，
腳本會逐條檢查並在終端印出「[警告] …找不到詞條」。

## 五、與正式版（6064 + 模型）的對齊

原本是 `_offline_reply` 的 1:1 移植。這一版按 6064 的**系統提示詞**補了六件事，
讓「沒有模型的離線版」行為更接近「有模型的正式版」：

| # | 正式版 prompt 的要求 | 離線版原本 | 現在怎麼做 |
|---|---|---|---|
| 1 | **嚴格語言匹配**：用戶用簡體就回簡體、繁體回粵語、英文回英文 | 綁死 UI 的 `?lang=` | 逐句用「繁體專用字 vs 簡體專用字」投票（`detectLang`），回覆與 UI 語言脫鉤 |
| 2 | 趣味小考官：出 **一題** 現實生活進階題，判對錯 + 原因 + 鼓勵 | 從 28 題裡隨機，答對只講「答對啦」 | 新增 15 題進階題庫（奶茶杯、洗頭水樽、錫紙、破玻璃杯…），桶別覆蓋四色；答對／答錯／聽唔明分三種回應，題目會記住等你答 |
| 3 | 遊戲外物品要**引導至回收點** | 只講「唔可以丟四色桶」 | 後面加一段：拿去「綠在區區」／屋苑回收箱／原店，唔肯定問老師家人 |
| 4 | 安全界線：情緒支援、不收集個資、離題溫柔帶回 | 只有一條泛用兜底 | 加情緒支援話術（先安慰→鼓勵找老師家人）、個資守門（電話／學號／身份證）、離題用主題詞閘門避免亂配 FAQ |
| 5 | 四色分類要講到具體例子 | 只列四個桶名 | 四色總覽補例子（報紙、紙箱、乾淨書本、飲品膠樽、鋁罐、污糟紙巾…） |
| 6 | 代碼只在分類條件／除錯出現，且用 `<details>` 做「點擊翻譯」 | 只有一條 `if` 模板 | 保留 `if`，另加 `and` 兩條件的版本（都 ≤ 3 行、都可折疊），其餘情況不出代碼 |

同時把 **27 條 FAQ 與 6 條關卡提示翻成三語**（含題目本身，否則簡體／英文問句匹配不到），
並補了 28 條同義問法（「為什麼要把垃圾分開」→ 接到「為什麼要分四個桶」）。

### 驗證方式（不是「看著像」）

| 檢查 | 方法 | 結果 |
|---|---|---|
| 分類事實 | 67 件物品 × 3 語 = 201 次查詢，比對靜態版與 Python 版的 `lookupItem` | 0 不一致 |
| 答非所問 | 同一批查詢，檢查回答是否提到正確的桶 | 0 條 |
| 對齊能力 | 16 個場景（三語切換、進階出題、答錯→答對、回收點、情緒、個資、離題、關卡提示、代碼折疊） | 全過，0 JS 錯誤、0 HTTP ≥400 |
| 整頁 | 1440px 與 390px 實跑，切語言、iframe 載入、橫向溢出 | 通過（溢出 0px） |

> 逐字比對（83 題）已經不再成立 —— 兩邊文案刻意不同了。要緊的是「事實一致」，所以改用上表的檢查。

### 三處刻意保留的差異（不打算改）

| # | 差異 | 原因 |
|---|---|---|
| 1 | 句子裡有具體物品時，先回答物品，再回答「四色總覽」 | 英文 `PAT_FOUR` 會命中 "which **bin**"，照原順序問 "Which bin for a plastic bottle?" 會拿到總覽而不是答案 |
| 2 | 物品名只取詞條第一段（「充電電池、鈕扣電池、鉛蓄電池」→「充電電池」） | 照原樣會變成「充電電池、鈕扣電池、鉛蓄電池唔可以丟四色桶」，像在唸清單 |
| 3 | FAQ 加主題詞閘門（相似度 0.62 且句中有主題詞，或相似度 ≥ 0.9） | 英文短句字集重疊容易誤配："how do i make a cake" 會撞到 "how do i find the mistake" |

另外：抽題是隨機的（`Math.random`），每次不同屬正常。

## 六、已知限制

- **只答詞庫內的問題。** 46 條物品、28 題題庫 + 15 題進階題、27 條 FAQ（×3 語）、5 關提示；
  範圍外的問題會回「我仲未夠聰明答這條」並給三個例子。這是離線版的設計，不是 bug。
- **不會推理、不會寫新句子。** 所有答案都是模板 + 詞庫組合；正式版模型能接住的自由問答，
  這裡只能靠詞庫與 FAQ 覆蓋。
- **語言判斷靠字集投票。** 一句話裡沒有任何繁簡差異字（例如「你好」）時，會沿用 UI 語言。
- **答案與遊戲畫面不一定同步。** 若 6064 改了關卡規則卻沒重跑生成腳本，小科會講舊規則。
- **FAQ 相似度門檻 0.62 + 主題詞閘門。** 太低會亂答，太高會常常兜底。
- 手機豎屏字級偏小（與 6064 相同），演示建議橫屏。
